# Веб-приложение для станции СМП и НМП

Веб-приложение для сотрудников скорой и неотложной медицинской помощи. Открывается в браузере планшета (адаптивная вёрстка, крупные кнопки). Данные вызовов и пациентов приложение нигде не хранит: оно посредник между планшетом и API медицинской организации. Локальная SQL-база (SQLite) содержит только пользователей, роли, права и журнал действий.

**Сдаётся как каркас:** подключение к реальному API, единый вход и перенос на другую СУБД выполняют специалисты заказчика, для них написана отдельная инструкция [INTEGRATION.md](INTEGRATION.md).

**Возможности:** список вызовов · информация о вызове · информация о пациенте · добавление случая медицинского обслуживания · добавление «Дневника» · запись пациента на приём · переход на портал врача.

## Два интерфейса (объединение веток inkoffTTV/backend-frontend и Frontend)

В одном приложении живут оба набора страниц, обе версии сохранены:

| Интерфейс | Адреса | Внешний вид | Данные |
|---|---|---|---|
| Корневой (inkoffTTV) | `/`, `/call/<id>`, `/patient/<id>`, `/admin`, формы `/…/new` | Bootstrap 5, `templates/`, `static/style.css` | через `api_client.py` | 
| Диспетчерский (из ветки Frontend) | `/fe/…` (список и поиск вызовов, карта, карточка вызова, маршрут, карточка пациента, админ-панель) | собственная тёмная тема, `templates/fe/`, `static/css/*.css`, `static/js/*.js` | через тот же `api_client.py` |

Вход в систему — один на оба интерфейса (`/login`). Страницы `/fe` дополнительно умеют: брать вызов фельдшером, этап бригады (принят → в пути → прибыл), завершение вызова (в т.ч. «ложный»), записи «информация про пациента» и «проблемы на вызове» с пометкой «некорректно». Эти действия требуют право `calls.manage` (см. «Роли и права») и идут через API (`PATCH /api/calls/{id}` и др.).

## Стек

Python 3 (код рассчитан на 3.8+), Flask, Jinja2, Bootstrap 5, requests, python-dotenv, logging, Gunicorn.

## Архитектура

```
Планшет (браузер) → Flask (app.py) → api_client.py → (HTTP, через VPN) → API СМП/НМП
                          ↑                ↑
                    templates/       нормализация полей
                    (Bootstrap)      + обработка ошибок + логи
```

| Файл | Назначение |
|---|---|
| `app.py` | маршруты, формы, логирование, страница ошибки |
| `fe_views.py` | второй интерфейс (ветка Frontend): маршруты с префиксом `/fe` |
| `api_client.py` | **всё** общение с API: запросы, таймауты, ошибки, нормализация полей |
| `auth.py` | вход/выход, проверка прав на маршрутах (`@permission_required`) |
| `db.py`, `schema.sql`, `seed.sql` | локальная SQL-база: пользователи, роли, права, журнал действий |
| `manage.py` | создание пользователей и смена ролей из командной строки |
| `config.py` | чтение настроек из `.env` / переменных окружения |
| `mock_api.py` + `mock_data.json` | заглушка API для разработки и демонстрации |
| `templates/`, `static/` | HTML-шаблоны (Bootstrap 5) и стили корневого интерфейса |
| `templates/fe/`, `static/css|js/` | шаблоны и стили интерфейса из ветки Frontend |

Шаблоны работают с фиксированными именами полей. Если реальное API называет поля иначе или у него другие адреса — правятся только константы `EP_*` и функции `_norm_*` в `api_client.py`. Вёрстка не затрагивается.

## Используемые endpoint'ы API

Адреса заданы константами в начале `api_client.py`. Сейчас — формат, который имитирует `mock_api.py`; под реальное API сверить с документацией заказчика.

| Действие в приложении | Метод и адрес | Тело запроса (JSON) |
|---|---|---|
| Список вызовов | `GET /api/calls` | — |
| Информация о вызове | `GET /api/calls/{call_id}` | — |
| Взятие/этап/завершение вызова | `PATCH /api/calls/{call_id}` | `active_owner, status_progress, completed, result` |
| Информация о пациенте | `GET /api/patients/{patient_id}` | — |
| Список случаев вызова | `GET /api/calls/{call_id}/cases` | — |
| Добавить случай | `POST /api/calls/{call_id}/cases` | `complaints, diagnosis, actions, outcome` либо `type, text, result` (интерфейс /fe) |
| Список дневников вызова | `GET /api/calls/{call_id}/diaries` | — |
| Добавить «Дневник» | `POST /api/calls/{call_id}/diaries` | `author, text[, type]` |
| Записи «информация о пациенте» | `GET/POST /api/calls/{call_id}/info` | `type, text, author` |
| Пометить запись некорректной | `POST /api/calls/{call_id}/info/{id}/mark_incorrect` | — |
| Записи «проблемы на вызове» | `GET/POST /api/calls/{call_id}/problems` | `type, text, author` |
| Пометить проблему некорректной | `POST /api/calls/{call_id}/problems/{id}/mark_incorrect` | — |
| Записи пациента на приём | `GET /api/patients/{patient_id}/appointments` | — |
| Записать на приём | `POST /api/patients/{patient_id}/appointments` | `specialty, date, time, comment` |

Успешный `POST` ожидает ответ `201` и JSON вида `{"status": "ok", "id": "..."}`. Если задан `API_TOKEN`, он отправляется заголовком `Authorization: Bearer <токен>`.

## Установка и запуск (Debian и производные, в т.ч. Astra Linux)

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip

cd smp_app
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# отредактируйте .env (см. таблицу ниже), рекомендуется задать свой SECRET_KEY:
python3 -c "import secrets; print(secrets.token_hex(32))"

# создать первого пользователя-администратора (пароль спросит в терминале, от 8 символов)
python manage.py create-user admin --role admin --name "Администратор"
```

База `data/app.db` создаётся автоматически при первом запуске. Остальных пользователей можно создать так же (`python manage.py --help`).

**Запуск с заглушкой API (разработка / демонстрация):**

```bash
# терминал 1
python mock_api.py                     # слушает 127.0.0.1:5001

# терминал 2 (в .env: API_BASE_URL=http://127.0.0.1:5001)
python app.py                          # http://localhost:8000 (только 127.0.0.1!)
```

Встроенный сервер Flask слушает только 127.0.0.1 — наружу приложение отдаёт Gunicorn.

**Боевой запуск через Gunicorn:**

```bash
gunicorn -w 2 -b 0.0.0.0:8000 app:app
```

Приложение открывается с планшета по адресу `http://<адрес-компьютера>:8000`. Если на компьютере включён файрвол, откройте порт 8000.

**На RPM-системах** (РЕД ОС, Альт, РОСА и др.) отличается только установка системных пакетов (`dnf install python3 python3-pip` или `apt-get install python3 python3-module-venv` в Альт); остальные шаги те же.

> Если на целевой ОС старый Python (например, 3.7 в Astra Linux 1.7), установите Python 3.8+ или используйте более свежий релиз ОС: актуальные версии Flask требуют Python 3.8 и выше.

## Настройки (`.env`)

| Переменная | Описание |
|---|---|
| `API_BASE_URL` | адрес API без завершающего `/` (для разработки `http://127.0.0.1:5001`) |
| `API_TOKEN` | токен авторизации, если API его требует |
| `API_TIMEOUT` | таймаут запроса к API, секунды (по умолчанию 5) |
| `DOCTOR_PORTAL_URL` | ссылка на портал врача; если пусто, кнопка неактивна |
| `SECRET_KEY` | ключ подписи сессий входа. Лучше задать свой; если пусто, создаётся файл `data/secret.key` (общий для всех worker'ов, вход не сбрасывается при перезапуске) |
| `DB_PATH` | файл SQLite (по умолчанию `data/app.db`) |
| `SESSION_HOURS` | сколько часов действует вход без активности (по умолчанию 24; каждый запрос продлевает срок) |
| `MAP_ENABLED`, `MAP_TILE_URL`, `MAP_ATTRIBUTION`, `MAP_ZOOM` | карта в карточке вызова: включение, адрес плиток (для закрытого контура свой сервер), подпись, масштаб |
| `LOGIN_MAX_ATTEMPTS`, `LOGIN_LOCK_MINUTES` | блокировка входа после неверных паролей (5 попыток, 5 минут) |
| `CACHE_TTL_SECONDS` | защищённый кэш чтения при обрыве связи (задача «со звёздочкой»): сколько секунд в ОЗУ хранятся последние загруженные вызовы и карточки пациентов (по умолчанию 120; 0 — выключить) |
| `SESSION_COOKIE_SECURE`, `TRUST_PROXY` | `1` при работе по HTTPS / за nginx |
| `LOG_DIR`, `LOG_LEVEL` | каталог и уровень логов (по умолчанию `logs`, `INFO`) |
| `MOCK_PORT` | порт `mock_api.py` (по умолчанию 5001) |

Файл `.env` в Git не попадает (`.gitignore`). Шаблон — `.env.example`.

## Bootstrap без интернета

По умолчанию стили и скрипты Bootstrap 5 подтягиваются с CDN. Если планшет или сервер работают без выхода в интернет, скачайте файлы и положите их в `static/vendor/`:

```
static/vendor/bootstrap.min.css
static/vendor/bootstrap.bundle.min.js
```

Приложение само переключится на локальные файлы.

## Обработка ошибок и логи

- Любая ошибка API (нет связи, таймаут, 4xx, 5xx, не-JSON ответ, не настроен адрес) превращается в понятное сообщение на экране; приложение не падает.

Дополнительно (задача «со звёздочкой») реализован защищённый кэш чтения: последние успешно загруженные список вызовов и карточки пациентов некоторое время хранятся в оперативной памяти в виде шифротекста (Fernet), ключ генерируется при старте процесса и на диск не пишется (модуль `secure_cache.py`, срок жизни `CACHE_TTL_SECONDS`). Если связь с API пропала, а кэш ещё не устарел, страницы списка вызовов и карточки пациента открываются в режиме «только чтение»: показываются последние известные данные с предупреждением о возрасте данных и временной недоступности создания новых записей (кнопка записи на приём при этом заблокирована). После перезапуска приложения ключ и кэш исчезают бесследно; при нескольких worker'ах Gunicorn у каждого процесса свой ключ и кэш.
- При ошибке сохранения формы введённые данные остаются на экране.
- Необработанные ошибки приложения показываются на странице «Внутренняя ошибка», а не как Traceback.
- Формы защищены от отправки с чужих страниц (CSRF-токен в сессии). Пользовательский текст экранируется шаблонизатором.
- Лог пишется в `logs/app.log` (ротация, 5 × 1 МБ) и в консоль: время, уровень, метод, адрес и код ответа API, ошибки интеграции, действия вроде «добавлен дневник по вызову N».
- **Тела запросов и ответов в лог не пишутся**, чтобы персональные и медицинские данные не попадали в файлы.

## Карта в карточке вызова

В карточке вызова показывается карта (Leaflet + плитки 2ГИС через локальный кэширующий прокси) с меткой места вызова и кнопки «Маршрут в Яндекс.Картах», «Яндекс.Карты», «2ГИС». Подробности офлайн-режима — в `README-OFFLINE.md`.

- Метка ставится по координатам вызова из API (поля `lat`/`lon`, см. `_norm_call` в `api_client.py`). Если координат нет, карта не показывается, остаются адрес и кнопки поиска по адресу.
- Карта не может сломать страницу: если библиотека или плитки не загрузились (нет интернета, закрытый контур), появляется надпись, а адрес, кнопки внешних карт и все остальные функции работают.
- Адрес пациента внешним сервисам автоматически не отправляется. Браузер планшета запрашивает у сервера плиток только фрагменты карты (по ним видно примерное место). Адрес уходит в Яндекс или 2ГИС только если сотрудник сам нажал на кнопку.
- Leaflet 1.9.4 и Bootstrap уже лежат в `static/vendor/`: внешние CDN не используются. Плитки 2ГИС кэшируются на сервере (`data/tiles`) и в браузере (service worker), поэтому карта работает без интернета. Отключить карту целиком: `MAP_ENABLED=0`.
- На планшете карта двигается двумя пальцами или кнопками «+/−», один палец прокручивает страницу.
- Тестовые координаты в `mock_data.json` приблизительные и к реальным адресам не привязаны; у третьего тестового вызова координат нет специально, чтобы показать запасной вариант.

## Положение планшета (геолокация)

Приложение подключается через VPN, поэтому определение места по IP-адресу не используется: он принадлежит VPN, а не планшету. Положение берётся с самого планшета (GPS или данные браузера).

- В карточке вызова кнопка «Показать моё местоположение»: браузер спросит разрешение один раз. Если разрешение уже выдано, положение определяется само при открытии вызова.
- Показывается расстояние до места вызова по прямой, точность определения, метка планшета с кругом точности на карте и кнопка «Маршрут от меня до места вызова» (Яндекс.Карты).
- Положение остаётся в браузере: оно не отправляется на сервер, не пишется в журнал и не сохраняется.
- Если разрешения нет, нет сигнала или истекло время, сотрудник видит понятное сообщение, а остальное приложение работает.
- **Нужен HTTPS.** Браузеры блокируют геолокацию на страницах без защищённого соединения (исключение только `localhost`). При открытии по `http://адрес:8000` кнопка покажет сообщение об этом. Настройка HTTPS описана в INTEGRATION.md.
- Точность зависит от планшета: без модуля GPS положение определяется по Wi-Fi и сотовой сети, оно грубее и в закрытой сети может не определиться вовсе.

## Роли и права

| Роль | Вызовы | Пациент | Случай, дневник | Запись на приём | Портал врача | Взятие/завершение вызова (`calls.manage`, /fe) | Администрирование |
|---|---|---|---|---|---|---|---|
| Администратор (`admin`) | да | да | да | да | да | да | да |
| Врач (`doctor`) | да | да | да | да | да | да | нет |
| Фельдшер (`paramedic`) | да | да | да | нет | да | да | нет |
| Диспетчер (`dispatcher`) | да | нет | нет | нет | нет | нет | нет |

Права проверяются на сервере (запрещённая страница отдаёт 403), кнопки без прав в интерфейсе скрываются. Каждый вход, просмотр вызова и пациента, добавление записей и отказ в доступе попадают в журнал действий (`/admin`). Тексты медицинских записей в журнал не пишутся. Состав ролей — рабочая заготовка: в ТЗ роль «уточняется».

## Известные ограничения

- Вход простой: логин и пароль в локальной базе. Единый вход организации (LDAP, ЕСИА и т.п.) подключается заменой функции `login` в `auth.py` (см. INTEGRATION.md).
- Адреса endpoint'ов и имена полей API заданы по заглушке; для реального API их нужно сверить с документацией заказчика (`EP_*` и `_norm_*` в `api_client.py`).
- Страница `/admin` только для просмотра; пользователей создают командой `manage.py`.
- HTTPS приложение само не обеспечивает: нужен nginx или другой прокси.
- Кэш чтения (задача со звёздочкой) хранится в каждом процессе отдельно: при нескольких worker'ах Gunicorn он не общий, и после перезапуска данные забываются (это осознанное ограничение по требованиям ТЗ — без записи на диск).

## Сценарий демонстрации

1. Запустить `mock_api.py` и приложение, войти под созданным пользователем. Открыть список вызовов (в режиме планшета, F12 в браузере).
   Для показа ролей создать диспетчера (`python manage.py create-user disp --role dispatcher`) и показать, что у него нет кнопок добавления, а прямые ссылки отдают 403. Журнал действий виден администратору на `/admin`.
2. Открыть вызов → карточку пациента → вернуться к вызову.
3. Добавить случай обслуживания и «Дневник»; они появятся на странице вызова.
4. Записать пациента на приём; запись появится в карточке пациента.
5. Нажать «Портал врача» (откроется новая вкладка).
6. **Ошибки API:** остановить `mock_api.py` (Ctrl+C), обновить список. Появится красное уведомление, приложение работает дальше, в `logs/app.log` видны записи `ERROR smp.api`. То же при неверном `API_BASE_URL`.

Готовые записи сценариев лежат в `demo/` архива `SMP-NMP-offline-map.zip`: `smp-nmp-paramedic.mp4` (фельдшер), `smp-nmp-admin.mp4` (администратор), `smp-nmp-demo.mp4` (общий), `smp-nmp-api-error.mp4` (ошибка API: отказ заглушки, кэш только для чтения, восстановление связи).
