# Инструкция для тех, кто подключает приложение к инфраструктуре

Приложение сдаётся как **каркас**: готовы экраны, роли, локальная SQL-база и точки подключения. Ниже — что именно нужно сделать на вашей стороне и где это менять.

## 1. Подключение к API СМП/НМП

Всё общение с API находится в одном файле `api_client.py`.

1. В `.env` задайте `API_BASE_URL`, при необходимости `API_TOKEN` и `API_TIMEOUT`.
2. Сверьте адреса endpoint'ов с документацией API: константы `EP_*` в начале `api_client.py`.
3. Сверьте названия полей: функции `_norm_call`, `_norm_patient`, `_norm_case`, `_norm_diary`, `_norm_appointment`. Каждая принимает JSON от API и возвращает словарь с **фиксированными** именами полей, которые используют шаблоны. Шаблоны менять не нужно. В `_pick(raw, "id", "call_id")` перечисляются возможные названия поля в ответе.
4. Если API принимает в `POST` другие названия полей, поправьте `create_case`, `create_diary`, `create_appointment`: сейчас они отправляют словарь из формы как есть.
5. Если API использует не Bearer-токен, а другую авторизацию (ключ в заголовке, Basic, сертификат), правьте начало функции `_request`.
6. Если API отдаёт XML или JSON-RPC, меняется только `_request` и нормализаторы.

Ожидания приложения от ответов: `GET` возвращает JSON (список или объект со списком внутри), успешный `POST` возвращает код 2xx. Любые другие ответы превращаются в понятное сообщение пользователю. Тексты сообщений находятся в `_request`.

Проверка после подключения: откройте список вызовов, вызов, пациента и отправьте три формы. Ошибки интеграции видны в `logs/app.log` (строки `ERROR smp.api`).

### Карта вызова

- Нужны координаты места вызова в ответе API. Названия полей, которые понимает `_norm_call`: `lat`/`latitude` и `lon`/`lng`/`longitude` (числа или строки). Если у API другие названия или координаты лежат во вложенном объекте, правьте `_norm_call`. Без координат карта не показывается, остаются кнопки поиска по адресу.
- Если API координат не отдаёт, их нужно получать геокодером (адрес → координаты). Это сознательно не сделано: адрес пациента не должен уходить в сторонний сервис без решения организации. Если разрешат, добавьте геокодирование в `maps.py` и в `_norm_call`.
- Плитки карты: браузер ходит на локальный `/tiles/{z}/{x}/{y}.png`, сервер скачивает их с `MAP_TILE_UPSTREAM` (по умолчанию 2ГИС) и кэширует в `data/tiles`. Service worker дополнительно кэширует плитки в браузере, поэтому карта работает без интернета. Для промышленной эксплуатации согласуйте права на плитки или укажите лицензированный источник.
- Leaflet и Bootstrap лежат в `static/vendor/`: CDN не используются. Детали — в `README-OFFLINE.md`.

### Работа через VPN и геолокация

- **HTTPS обязателен.** Геолокация в браузере (Chrome, Яндекс Браузер, Firefox и др.) работает только на страницах с HTTPS. Без него кнопка «Показать моё местоположение» выдаст сообщение и положение определено не будет. Нужен сертификат для адреса, по которому планшеты открывают приложение. Для закрытого контура подойдёт сертификат внутреннего удостоверяющего центра, при условии что его корневой сертификат установлен на планшетах.
- Положение определяет браузер планшета, а не сервер. Сервер его не получает, поэтому ничего настраивать на стороне API для этого не нужно.
- Из-за VPN все пользователи для сервера приходят с адресов VPN: в журнале действий (`audit_log.ip`) будут адреса VPN-сети, а не реальные.
- Планшет должен через VPN доставать до сервера плиток карты (`MAP_TILE_URL`) и, если файлы не лежат в `static/vendor/`, до CDN. Если VPN пропускает трафик только до сети организации, поднимите сервер плиток внутри неё.
- Планшеты без модуля GPS определяют положение по Wi-Fi и сотовой сети. Такое определение может быть грубым или недоступным; приложение показывает точность и предупреждает, если она хуже 1 км.
- Если организации нужно видеть положение бригад (отслеживание на стороне станции), этого в приложении нет: положение сознательно не передаётся на сервер. Для отслеживания нужно отдельное решение и согласование: это персональные данные сотрудников.

## 2. Пользователи и роли

Локальная база (SQLite, файл `DB_PATH`) хранит только пользователей, роли, права и журнал действий. **Данные пациентов в ней не хранятся.**

Заготовка ролей: `admin`, `doctor`, `paramedic`, `dispatcher`. Права: просмотр вызовов, просмотр пациента, добавление случая, дневника, записи на приём, портал врача, администрирование. Состав — рабочая заготовка: ТЗ говорит, что роль «уточняется».

- Первый запуск: `python manage.py create-user admin --role admin --name "Администратор"`.
- Остальные команды: `python manage.py --help`.
- Поменять набор ролей и прав: `seed.sql` (для новой базы) или обычные SQL-запросы к таблицам `roles`, `permissions`, `role_permissions` (для живой базы).
- Новое право: добавить строку в `permissions`, выдать нужным ролям, поставить `@permission_required("код.права")` на маршрут в `app.py`.

**Вход сделан простой: логин и пароль в локальной базе.** Если у вас есть единый вход (LDAP, Active Directory, ЕСИА, Keycloak и т.п.), заменяется только функция `login` в `auth.py`: после успешной проверки учётных данных нужно положить `session["uid"]` пользователя из таблицы `users`. Роли и права продолжат работать.

## 3. База данных

Схема — `schema.sql`, начальные данные — `seed.sql`. Все обращения к базе находятся в `db.py`.

Для перехода на PostgreSQL или другую СУБД:
- замените `connect()` и `get_db()` в `db.py`;
- поправьте SQL по комментариям в начале `schema.sql` и `seed.sql` (типы ключей, `datetime('now')`, `INSERT OR IGNORE`);
- параметры в запросах сейчас в стиле SQLite (`?`); у `psycopg2` это `%s`.

Резервное копирование SQLite: копия файла `DB_PATH` при остановленном приложении или командой `sqlite3 app.db ".backup копия.db"`.

## 4. Запуск в продакшене

- `gunicorn -w 2 -b 127.0.0.1:8000 app:app` за nginx (или другим прокси) с HTTPS (без него не заработает геолокация планшета).
- В `.env`: `SECRET_KEY` (свой; иначе используется файл `data/secret.key`, его нужно беречь так же, как пароль), `SESSION_COOKIE_SECURE=1`, `TRUST_PROXY=1`.
- Права на каталоги `data/` и `logs/`: запись для пользователя, от которого работает приложение. Каталог `data/` не должен быть доступен из веба.
- Автозапуск: unit-файл systemd с `ExecStart` из строки выше и `WorkingDirectory` в каталоге проекта.
- Mock-API (`mock_api.py`) в продакшене не запускается.

## 5. Что осталось на вашей стороне

| Что | Почему |
|---|---|
| Реальные endpoint'ы и поля API | заданы по заглушке |
| Координаты вызова в API и лицензия на плитки 2ГИС | задано по заглушке; права на плитки нужно согласовать |
| Утверждённый состав ролей и прав | в ТЗ роль «уточняется» |
| Единый вход, если он требуется | сейчас локальные логины |
| HTTPS и прокси | приложение само шифрование не делает; без HTTPS не работает геолокация планшета |
| Требования к хранению журнала и персональных данных | сроки хранения и защита задаются политикой организации и законодательством, в код не заложены |
| Кэш с шифрованием (задача со звёздочкой) | не реализован |
| Проверка на целевой ОС (Astra, РЕД ОС и др.) | на ней приложение не запускалось |
