# Инструкция по запуску и работе с приложением СМП/НМП

Документ для того, кто будет запускать приложение и показывать сценарии. Полное описание архитектуры — в [README.md](README.md), офлайн-карта — в [README-OFFLINE.md](README-OFFLINE.md), подключение со стороны заказчика — в [INTEGRATION.md](INTEGRATION.md), исходное ТЗ и разбор по пунктам — в [docs/TZ.md](docs/TZ.md).

## 1. Что именно запускается

Веб-приложение на Python 3 + Flask. Открывается в браузере планшета (адаптивная вёрстка). Есть два интерфейса с общим входом:

| Интерфейс | Адреса | Для чего |
|---|---|---|
| Корневой | `/`, `/call/<id>`, `/patient/<id>`, `/admin` | базовый сценарий ТЗ: список вызовов, вызов, пациент, формы, портал врача |
| Диспетчерский `/fe` | `/fe/`, `/fe/call/<id>`, `/fe/patient/<id>`, `/fe/admin` | карта 2ГИС, приём/завершение вызова, этапы бригады, журнал, админ-панель |

Данные вызовов и пациентов приложение **не хранит у себя**: оно ходит в API через `api_client.py`. Локальная SQLite-база `data/app.db` содержит только пользователей, роли, права и журнал действий. В демонстрации вместо боевого API работает собственная заглушка `mock_api.py` (порт 5001) с тестовыми данными.

## 2. Быстрый старт на одном компьютере

Нужны Python 3.8+ и Debian/Астра или другая ОС с Python.

```bash
cd smp_app
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# В .env обязательно выставьте:
#   API_BASE_URL=http://127.0.0.1:5001
#   SECRET_KEY=<сгенерированный ключ: python3 -c "import secrets; print(secrets.token_hex(32))">
#   DOCTOR_PORTAL_URL=<ссылка на портал врача, если есть>
```

Создайте пользователей (пароль спрашивается в терминале, не короче 8 символов):

```bash
python manage.py create-user admin     --role admin      --name "Администратор"
python manage.py create-user doctor    --role doctor     --name "Врач"
python manage.py create-user feldsher  --role paramedic  --name "Фельдшер бригады"
python manage.py create-user disp      --role dispatcher --name "Диспетчер"
```

Другие команды: `python manage.py list-roles`, `list-users`, `set-password <логин>`, `set-role <логин> <роль>`, `activate/deactivate <логин>`, `python manage.py --help`.

Запуск в двух терминалах:

```bash
# терминал 1 — заглушка API
python mock_api.py                     # 127.0.0.1:5001

# терминал 2 — приложение
python app.py                          # http://127.0.0.1:8000/login
```

Откройте `http://127.0.0.1:8000/login`. В готовом демонстрационном архиве работают учётные записи `doctor / demo12345` и `admin / demo12345`; перед реальным использованием пароли нужно заменить.

Для показа с планшета в сети вместо `python app.py` используется Gunicorn:

```bash
gunicorn -w 2 -b 0.0.0.0:8000 app:app
```

Открывать с планшета: `http://<адрес-компьютера>:8000` (при включённом файрволе открыть порт 8000). Геолокация в браузере требует HTTPS — схему проксирования и подключение реального API смотрите в [INTEGRATION.md](INTEGRATION.md).

## 3. Роли и права

Состав ролей — рабочая заготовка: в ТЗ конкретная роль «уточняется». Права проверяются на сервере: нет права — страница отдаёт 403, кнопки в интерфейсе скрываются.

| Роль | Что может |
|---|---|
| `admin` — администратор | всё, включая пользователей, журнал и админ-карту |
| `doctor` — врач | вызовы, пациент, случай, дневник, запись на приём, портал врача, взятие/завершение вызова |
| `paramedic` — фельдшер бригады | то же, кроме записи на приём и администрирования |
| `dispatcher` — диспетчер | только просмотр списка и карточки вызова |

В интерфейсе `/fe` роли `doctor` и `paramedic` выглядят как один «фельдшерский» экран; разница — доступ к записи на приём.

## 4. Основные сценарии

### Фельдшер (`/fe/`)

1. Войти под `feldsher` (или `doctor`).
2. Список вызовов: «Обновить», сортировка «Ближайший вызов», поиск.
3. «Карта» — метки вызовов, зум, popup, кнопка «Показать моё местоположение»; карта работает и без сети (тайлы 2ГИС из кэша).
4. Открыть вызов → «Взять вызов» → этапы «в пути» / «прибыл».
5. Добавить «Информацию про пациента», «Проблемы на вызове», случай обслуживания и «Дневник». Ошибочную запись можно пометить как некорректную.
6. Завершить вызов (результат — «завершён» или «ложный»).

### Врач

1. Список вызовов → карточка пациента.
2. «Записать на приём к врачу» — дата, время, специальность, примечание.
3. «Портал врача» в шапке открывает внешний URL из `.env` в новой вкладке. Если `DOCTOR_PORTAL_URL` пуст, кнопка неактивна.

### Администратор

1. `/fe/admin` — сводка, пользователи, история вызовов; отдельная карта `/fe/admin/map/call/<id>` с меткой вызова и машины, маршрутом и офлайн-тайлами.
2. `/admin` — пользователи, матрица ролей и прав, журнал действий (вход, просмотр, добавления, отказы в доступе). Страница только для чтения; пользователей создают и меняют через `manage.py`.
3. Сброс активного вызова сотрудника — на `/fe/admin` (кнопка в списке пользователей).
4. Смена роли: `python manage.py set-role <логин> <роль>`.

### Диспетчер

Видит список и карточку вызова. Кнопок добавления, карточки пациента и портала нет; прямые ссылки на эти страницы дают 403.

## 5. Ошибки API, офлайн-режим и кэш

- Если остановить `mock_api.py` или указать неверный `API_BASE_URL`, приложение **не падает**: на экране появляется понятное красное/жёлтое сообщение, остальные страницы работают. В `logs/app.log` пишутся строки `ERROR smp.api` (тел запросов и ответов в лог не попадают).
- Последние успешно загруженные список вызовов и карточки пациентов хранятся в ОЗУ в зашифрованном виде (Fernet, ключ создаётся при старте процесса и не пишется на диск). При обрыве связи они показываются с предупреждением о возрасте данных, в режиме «только чтение»; запись на приём заблокирована. Срок жизни задаётся `CACHE_TTL_SECONDS` (по умолчанию 120 с, `0` — выключить). После рестарта кэш и ключ исчезают.
- Карта 2ГИС работает без интернета: плитки кэшируются на сервере (`data/tiles`) и в браузере service worker'ом `smp-offline-v3`. Подробности — [README-OFFLINE.md](README-OFFLINE.md).
- Внешние CDN не используются: Bootstrap, Leaflet и плитки лежат локально.

## 7. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| «Нет связи с сервером» | запущен ли `mock_api.py`, верен ли `API_BASE_URL` в `.env` |
| 403 на странице | у пользователя нет нужного права — посмотреть `python manage.py list-users` и матрицу на `/admin` |
| Пустой список вызовов | есть ли данные в заглушке; открыть `/api/calls` на порту 5001 |
| Карта серая | прогрузить тайлы онлайн один раз; проверить `MAP_ENABLED` и `data/tiles` |
| Вход не сохраняется | задан ли `SECRET_KEY`; при работе за nginx — `TRUST_PROXY=1`, `SESSION_COOKIE_SECURE=1` |
| Логи | `logs/app.log` (ротация 5 × 1 МБ) и консоль процесса |
